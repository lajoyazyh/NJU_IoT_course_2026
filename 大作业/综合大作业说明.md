# 期末大作业要求

## 基于多人人脸检测与表情识别的课堂状态分析系统

### 作业背景与选题说明

本次期末大作业要求学生完成一个“基于多人人脸检测与表情识别的课堂状态分析系统”。该方向与前两次实验课程中的视觉识别任务具有一定关联，但不再只是完成单张人脸表情分类或单个手势识别，而是进一步扩展为多人场景下的检测、分类、统计、状态分析和可视化展示。

本项目在本地运行 Python 程序，完成系统演示。

### 作业目标

1. 能够对输入图片、视频或摄像头画面进行人脸检测，自动框出画面中的多个人脸。
2. 能够统计画面中的人数，并对每个人脸区域进行表情识别。
3. 能够汇总不同表情类别的人数和比例，形成表情分布统计结果。
4. 能够根据表情分布给出简单的课堂状态判断，例如“状态良好”“状态平稳”“需要关注”等。
5. 能够通过本地可视化界面展示输入图像、检测框、表情标签、人数统计、表情统计和历史记录。
6. 能够保存每次检测结果，形成 CSV、JSON 或 Excel 格式的运行记录。

### 系统总体流程

图片 / 视频 / 摄像头输入

→ 人脸检测与人脸框定位

→ 人脸区域裁剪与预处理

→ 单个人脸表情识别

→ 多人表情结果汇总

→ 人数统计与表情分布统计

→ 课堂状态判断

→ 结果可视化与记录保存

**示例输出：**

- 检测人数：5
- 表情统计：
  - Happy: 2 人
  - Neutral: 2 人
  - Sad: 1 人
  - Angry: 0 人
- 课堂状态：整体状态较积极

## 系统模块要求

### 数据输入模块

系统需要支持至少一种数据输入方式。考虑到部分学生电脑摄像头可能不可用，本作业不强制要求实时摄像头。

| 层次 | 要求 |
|---|---|
| 基础要求 | 支持图片上传识别。用户上传一张包含多个人脸的图片，系统完成检测和统计。 |
| 进阶要求 | 支持视频上传识别。系统对视频中的若干帧进行分析，并统计整体表情分布。 |
| 加分要求 | 支持摄像头实时识别。系统能够实时检测画面中的人脸与表情。 |

### 人脸检测模块

系统需要先检测图像中的人脸位置，而不是假设图片中只有一个人脸。人脸检测模块需要完成以下功能：

- 检测画面中所有人脸；
- 返回每个人脸的边界框坐标；
- 在原图中用矩形框标出人脸位置；
- 统计检测到的人脸数量。

可选方法包括 OpenCV Haar Cascade、OpenCV DNN、MediaPipe Face Detection、MTCNN、YOLO-face、RetinaFace 等。对大多数学生，推荐使用 OpenCV Haar Cascade 或 MediaPipe Face Detection。

### 表情识别模块

在人脸检测之后，系统需要对每一个人脸区域进行表情识别。基本流程如下：

检测到人脸框 → 裁剪人脸区域 → 调整尺寸并预处理 → 送入表情识别模型 → 输出表情类别和置信度

| 表情类别 | 含义 |
|---|---|
| Happy | 开心 |
| Neutral | 平静 |
| Sad | 悲伤 |
| Angry | 生气 |
| Surprise | 惊讶 |
| Fear | 害怕 |
| Disgust | 厌恶 |

基础版本不要求支持所有类别，支持 4 至 7 类表情即可。学生可以使用课堂实验中的表情识别模型，也可以使用开源预训练模型或 FER2013 训练好的模型。

### 多人统计模块

这是本次大作业区别于第一次实验的重要部分。系统需要对所有检测到的人脸表情进行汇总统计，至少包括：

- 检测到的总人数；
- 每类表情的人数；
- 每类表情的比例；
- 主要表情类别；
- 整体课堂状态判断。

**示例：**

- Total People: 6
- Expression Count:
  - Happy: 2
  - Neutral: 3
  - Sad: 1
  - Angry: 0
- Expression Ratio:
  - Happy: 33.3%
  - Neutral: 50.0%
  - Sad: 16.7%
  - Angry: 0.0%
- Main Expression: Neutral

### 课堂状态分析模块

系统不能只停留在识别表情，还需要根据统计结果给出一个简单的课堂状态判断。学生可以自行设计规则，也可以参考下面的示例规则。

| 统计条件 | 状态判断 |
|---|---|
| Happy + Neutral 占比 ≥ 70% | 课堂状态良好 |
| Sad + Angry 占比 ≥ 40% | 课堂状态较低落或需要关注 |
| Neutral 占比最高 | 课堂状态平稳 |
| Surprise 占比较高 | 课堂注意力波动较大 |
| 检测人数为 0 | 未检测到学生 |

### 可视化界面模块

学生需要实现一个本地可视化界面。推荐使用 Streamlit 或 Gradio，因为它们不需要复杂前后端开发，运行一行命令即可打开本地交互界面。

界面至少应包含以下内容：

- 图片上传区域：用户可以上传一张多人图片；
- 原始图片展示区域：显示用户上传的原图；
- 检测结果图片展示区域：显示画框后的人脸检测结果，并标注表情类别和置信度；
- 人数统计区域：显示检测到的总人数；
- 表情统计区域：显示各类表情的人数和比例；
- 课堂状态区域：显示系统判断结果；
- 历史记录区域：展示最近几次检测结果。

### 数据记录模块

每次检测完成后，系统需要保存一条记录。推荐保存为 CSV 文件，以降低实现难度。

| 时间 | 图片名称 | 检测人数 | Happy 人数 | Neutral 人数 | Sad 人数 | Angry 人数 | 主要表情 | 课堂状态 |
|---|---:|---:|---:|---:|---:|---:|---|---|
| 2026-xx-xx 10:20 | class1.jpg | 5 | 2 | 2 | 1 | 0 | Happy | 良好 |
| 2026-xx-xx 10:25 | class2.jpg | 6 | 1 | 4 | 1 | 0 | Neutral | 平稳 |

- 能够对每个人脸进行表情识别；
- 能够在图像中框出人脸并标注表情类别；
- 能够统计不同表情的人数；
- 能够给出简单课堂状态判断；

#### 加分项

- 支持摄像头实时识别；
- 支持表情统计图表展示；
- 支持导出检测结果图片；

## 延伸拓展任务

### 课堂状态时序分析与预警任务

#### 任务背景

单次图片分析为静态快照，实际课堂需连续帧/多时段趋势判断，如后半段学生普遍低落、注意力下滑。本任务扩展为时序化课堂状态分析。

#### 任务目标

1. 视频关键帧采样：按 1 秒 1 帧抽取，逐帧检测、表情识别，输出时序表情序列。
2. 滑动窗口统计：以 5 帧为窗口，计算窗口内表情均值、方差，识别状态突变。
3. 三级预警机制：
   - 绿色：连续 10 帧状态良好；
   - 黄色：连续 5 帧状态平稳但中性占比过高；
   - 红色：连续 3 帧低落 / 注意力波动，触发预警提示。
4. 时序可视化：界面新增折线图，横轴为时间 / 帧，纵轴为表情占比，叠加预警标记。
5. 时序日志保存：CSV 新增帧号、时间戳、窗口均值、预警等级字段。

#### 验收标准

- 可处理 1 分钟课堂视频（单个学生视频 / 多人学生视频均可，可以在 B 站搜索“上课打瞌睡视频”等找一个视频），输出时序表情数据；
- 正确识别至少 1 种状态突变并触发对应预警；
- 生成时序分析图表、预警日志及趋势分析结论。

## 评分标准

- 运行稳定性（10）：正常无报错 10，异常酌情扣分
- 数据输入（8）：图 / 视频 / 摄像头全支持 8，仅图片 4
- 人脸检测（15）：多人精准 15，漏检误检重扣分
- 表情识别（15）：5--7 类准确 15，类别少、准确率低扣分
- 统计与状态（12）：完整统计 + 状态判断 12，缺失扣分
- 可视化界面（12）：Streamlit / Gradio 完整美观 12，简陋扣分
- 数据记录（8）：CSV 字段完整 8，缺失或无记录扣分
- 基础加分（≤5）：视频、摄像头、图表、导出、批量、自定义规则
- 延展任务（≤5）：时序采样、滑动窗口、三级预警、时序可视化、日志
- 文档提交（10）：代码 + 依赖 + 说明 + 报告齐全 10，不全扣分
